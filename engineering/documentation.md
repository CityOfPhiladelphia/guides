- Write the documentation before opening the PR, and update it again afterwards. Writing it first helps set goals for the work; revisiting it keeps it accurate.
- Documentation **must** include an example of how to run the code.
- The writer **must** run every script and command included in the documentation.
- Remove all boilerplate (from templates or generated content) before review.
- The writer **must** read through the documentation and confirm it can be understood. Reviewers do the same (see [Code Review](code-review.md)).
